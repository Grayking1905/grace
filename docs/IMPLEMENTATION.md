# Grace implementation status

19 October 2026 · Development release 0.1.0 · Live organization and team Home

The original PRD remains the source of product scope. This document records what is implemented and what still needs development. The aspiration to exceed Jira is a product direction, not a claim that this first release achieves feature parity.

## Delivered foundation and working flows

- Role-scoped Home with SQL aggregates, completion/status graphs, daily delivery activity, project coverage and overdue/flagged work. Organization admins see all teams; other roles see their team and accessible assigned/linked projects. Project-to-team ownership is explicit, transactional and versioned; it never grants private-project membership.
- Durable Home activity records sign-ins/sign-outs and core work changes without publishing passwords, session tokens, raw audit details or comment bodies. Visibility is enforced before cursor pagination, including current access after issue moves. Connected-member presence deduplicates browser clients; real-time invalidations, reconnect validation and a 15-second refresh fallback update Home. Presence is local to one API instance; distributed presence and replay remain future work.

- A simplified sidebar with six primary destinations, Reports, Settings and an expandable More tools group. Personal work is one searchable list with type/view filters, whole-row opening and versioned completion actions. Team dashboards use compact summaries and tabs; forms progressively disclose optional fields. Desktop and mobile layouts were checked in the local browser.
- A distinct Team Manager role: own-team layout, work assignment and ordinary member/lead/viewer role changes. Employee IDs, transfers, manager appointments, invitations and capability rules stay with organization admins. Migration 8 preserves existing employee roles and custom permission rules. Private-project editing restrictions also apply to manager work dialogs and completion controls.
- Clipboard actions provide manual-copy fallback when browser clipboard access fails. Settings links connect team management, account security and administration; the People directory label no longer appears as an inactive button.

- React, TypeScript, Vite, TanStack Query, Tiptap, dnd-kit, Socket.IO, and an Express/TypeScript API.
- An original light theme with warm white, sage, lavender, local variable fonts, responsive layouts, dialogs, visible focus, toasts and shortcut help. The updated type scale uses 15 px body controls, 14 px secondary labels, 13 px captions and 16 px reading text.
- MySQL and SQLite SQL adapters, parameterized queries, schema export, foreign keys, indexes, transactional mutations, version conflict checks, and atomic issue keys. Numbered additive migrations record the v2 planning baseline and v3 sprint lifecycle snapshots without resetting user records, custom statuses, or custom columns.
- Workspace signup and login, session refresh/logout, request validation, CSRF checks, rate limiting, HTML sanitization, workspace isolation, private projects, and basic workspace/project roles.
- Core project, issue, board, backlog, sprint, collaboration, notification, search, Pages, reports, import/export, and manager flows described in the README.
- Workspace creation and switching, single-use expiring invitation links bound to an email, invitation status/revocation, active-session inspection, individual session revocation, sign out of other sessions, and sign out everywhere. Switching rotates the current session into the selected workspace; regular login still initially selects the first membership.
- Project administration for names, descriptions, visibility, lead changes, explicit member/admin/viewer roles, member removal, archive, and restore. Workspace owners/admins retain their access; workspace viewers cannot gain write access through a project role. Issue trash exposes the 30-day admin recovery window and flags projects that must be restored first.
- Modules with names, descriptions, leads, dates, explicit lifecycle states, many-to-many issue membership, versioned edits, archive/restore, and server-computed issue/point progress. Completing a module rejects unfinished linked issues; its manual state and live issue progress remain distinct.
- Cycle planning with atomic mixed scope changes, one active cycle per project, carry-over, immutable start/completion snapshots, scope-change history, real daily burndown, and CSV export. Final scope includes unfinished work carried into the next cycle; later issue edits do not rewrite captured completion totals.
- Transactional bulk status, assignee, priority, cycle, label, and soft-delete operations. Every selected issue is permission-checked and version-checked; any invalid or stale item aborts the whole batch. Unspecified fields remain unchanged.
- Rich-editor slash commands, nested checklists, tables with row/column controls and resizing, link editing and validation, headings, formatting, quotes, lists, code blocks, and dividers. Descriptions and Pages use a shared server sanitizer that preserves supported editor nodes.
- Saved private/workspace Views can be created, applied, renamed, edited, shared, and deleted. GQL is validated before a view is saved. Private views are editable only by their owner; shared views by their owner or workspace admins. Viewer roles cannot mutate views.
- Organization overview, employee ID + organization code + password sign-in, automatic member dashboard routing, admin-created team dashboards, configurable sections and team-role capabilities. Migration 7 assigns stable IDs without resetting existing records. Email-bound invitations carry the employee’s team assignment. See [organization setup](ORGANIZATION.md).
- Unified Create menu; SQL-backed BRDs, daily tasks and release versions with rich descriptions, owners, dates, states, linked issues, permission checks, version conflicts and deletion. My Work separates daily tasks, issues, bugs, features, BRDs and versions. Entire board cards open and drag; Enter opens, Space moves, Escape cancels.
- Email verification, password recovery, SMTP delivery and member deactivation. Reset and verification tokens are hashed, expiring and single-use; password reset revokes sessions. Mail delivery is scheduled after SQL commit. SMTP was tested against a local test mailbox; the user configures their relay in `.env`.
- Distinct project configurations, rich issue templates, standalone issue moves with stable key aliases, backlog ranking, watcher assignment, comment deletion and mentions, and per-event in-app/email notification preferences.
- Module members, dependency cycle prevention, cross-project initiatives, cycle retrospectives, SQL summary reports, MySQL full-text search, optional keyset bootstrap pagination, and virtualization for large issue lists and board columns.
- AES-256-GCM encrypted SQL backup/restore, empty-target validation and session/token invalidation on restore. Uploads require a separate backup. The real MySQL 8.4.11 integration suite covers migrations, concurrent keys, aliases, organization work and restore. A MySQL integration workflow is included; remote CI has not been run here.

## Deliberately limited first implementations

- **Workflows:** custom status columns, category mapping, naming, and WIP limits work. Every configured status can transition to every other status. Workflow graphs, role conditions, validators, post-functions, draft publishing, and migration between workflow versions are pending.
- **Boards:** one status-based board per project. Whole-card dragging, keyboard movement and virtualization above 100 items per column work. Swimlanes, multiple boards, persistent board filters and configurable status mappings remain pending.
- **Issue editing:** properties save inline, while descriptions and Pages use explicit saves. This release does not promise universal autosave or collaborative CRDT editing. Comments are plain text; descriptions and Pages are rich text.
- **Rich text:** the delivered editor supports slash commands, nested task lists, tables, headings, formatting, links, and code blocks. Image embeds, syntax highlighting, mentions, emoji picker, and concurrent shared editing remain pending. Checklists in descriptions/Pages do not create separate issues automatically.
- **Search:** global issue search uses a bounded SQL endpoint with MySQL full-text search (SQLite uses LIKE). GQL still evaluates server-loaded visible issues with length/token/record limits. Comment text, fuzzy matching, people search and a scale-out adapter are pending.
- **GQL:** supports AND/OR/NOT, parentheses, comparisons, contains, lists, empty checks, one ORDER BY, currentUser(), openSprints(), now(), and startOfWeek(). Historical WAS/CHANGED operators, autocomplete, multiple sort columns, and full JQL compatibility are pending. Query length is bounded and inputs are parsed without eval or SQL interpolation.
- **Reports:** SQL summaries, status/workload, worklog time, created/completed activity, closed-sprint velocity, cycle burndown, scope history and retrospective notes work. Burndown actuals begin at the v2 baseline; earlier/future days are null. V3 start/completion snapshots preserve final scope; older cycles explicitly use current membership. Burnup, CFD, cycle/lead time, cost reports, chart export and freely configurable dashboard gadgets remain pending.
- **Timeline:** date-based timelines, module dependencies, initiative portfolio and release records work. Dependency routing on the Gantt view, drag scheduling, baseline comparison, critical path and a calendar view remain pending.
- **Jira import:** supports Summary, key, status, type, priority, simple description, and story points in CSV or JSON. Unknown status names map to the first configured status with a warning. It creates new issues after preview and preserves the original key in the description. Assignee mapping, epics/links/sprints, Atlassian Document Format, attachments, diff/upsert, direct Jira APIs, and the PRD’s 95% fidelity target remain pending. Re-import is not deduplicated.
- **Manager suite:** basic capacity estimates, standups, stale work, risk state, and Markdown digest work. Capacity uses an explicit hours-per-point assumption and a two-week horizon; it is not time tracking. Leave, loaned time, calendar availability, private 1:1 notes, personal todos, meeting management, and scheduled digests remain pending.
- **Templates:** Scrum, Kanban, Bug, Basic and Minimal configurations have distinct states, supported types, default types and cycle settings. Issue templates store reusable rich descriptions and defaults. Visual workflow conditions remain pending.
- **Real time:** authenticated workspace rooms send invalidation events without record contents. Clients refetch through access-checked endpoints. Redis fan-out, missed-event replay, presence/typing indicators, and horizontal scaling remain pending.
- **Permissions:** organization roles, employee/team assignment, team capabilities, private projects, project roles, author/owner checks, bulk-item checks and recovery administration are enforced. Issue-level security, advanced workflow permission schemes and an instance-admin console remain pending. Team dashboard sections are layout settings; disabling a section does not replace authorization.
- **Attachments:** protected local download and a 25 MB upload limit work. Orphan cleanup, virus scanning, image previews, quotas, and S3-compatible object storage remain pending.

## Remaining expansion work

- The optional paginated bootstrap API is implemented; the main application still uses a full issue bootstrap. Complete incremental client loading and pagination across every entity. Organization work views currently show the most recent 500 accessible records.
- Validate the PRD’s load targets under realistic concurrency and data volume. Local 500-card measurements are limited development evidence, not validation at 10,000 users or millions of issues.
- Broaden end-to-end interaction automation, assistive-technology and contrast audits, and security review. Current coverage includes rich editor/Page regressions, organization interaction tests, local SMTP, authenticated multi-client invalidation/deactivation, attachments, tenant isolation and selected automated WCAG A/AA checks.
- Invitation delivery, durable queued email retries and sending through the user’s real SMTP relay remain unverified; invitation links are currently shared manually.
- Issue moves preserve aliases but intentionally reject parent/child hierarchies and closed-cycle work until coordinated hierarchy moves are implemented.
